# 🎙 RSS Feed Maintenance Guide

The RSS Feed is the "Product" of this system. If it breaks, users cannot listen to their content.

## 📍 Critical Files
*   **Generator Logic**: `app/api/feed/route.ts`
    *   This file constructs the XML string manually or using a helper.
*   **Data Source**: `api-utils.ts` or direct Prisma calls within the route.
*   **Validation**: `lib/xml-utils.ts` (if it exists, checks for illegal characters).

## ✅ RSS Compliance Checklist
Every time you modify the Feed Generation logic, you **MUST** ensure:

1.  **Strict XML Structure**:
    *   `<rss version="2.0" xmlns:itunes="...">` header is present.
    *   All user input (Titles, Descriptions) is wrapped in `<![CDATA[ ... ]]>`.
    *   Special characters (`&`, `<`, `>`) outside CDATA are escaped.
2.  **Podcast Player Requirements** (Apple/Castbox/Pocket Casts):
    *   `<itunes:image>`: Must be a valid URL (usually the channel thumbnail).
    *   `<enclosure>`: The audio file URL, length (bytes), and type (`audio/mpeg`). **CRITICAL**: Without this, it's not a podcast.
    *   `<guid>`: Unique ID for the episode. Usually `video.youtube_video_id` or `podcast.guid`.
3.  **Performance**:
    *   The feed should be **Cached**. Querying 50+ videos and summaries per request is too slow.
    *   Use `Next.js` Request Memoization or `unstable_cache`.

## 🛠 Troubleshooting & Validation
When a user says " The feed won't load":

1.  **Validator**: Copy the Output XML to [Castbox Podcaster Tools](https://castbox.fm/podcasters-tools) or [W3C Validator](https://validator.w3.org/feed/).
2.  **Common Errors**:
    *   **"XML Parsing Error"**: Often caused by a special character (emoji or control character) in a summary generated by AI.
        *   *Fix*: Ensure `strip_control_characters` is running on the Python side, or sanitized in JS.
    *   **"No Episodes"**: Check if `enclosure` tag is missing.
    *   **"Timeout"**: The database query took too long. Check if `VideoOrEpisode` join is optimized.
